# RL-XXX: Imperative ticket title

## Objective

State one observable outcome that a delivery agent can complete and verify.

## Technical constraints

- Type: `epic` or `story`.
- Epic: `RL-EXX` for stories; `none` for an epic.
- Depends on: ticket IDs or `none`.
- Add the implementation and compatibility constraints that cannot be delegated as design choices.

## Functional requirements

1. Express independently verifiable requirements in delivery order.
2. Use these requirements as the implementation task list for a story.
3. For an epic, enumerate the child stories and required outcome of each.

## Quality requirements

- State required tests, type checks, documentation, security, performance, and evidence.
- Require real checks; placeholder commands are not acceptable.

## Out of scope

- Exclude adjacent work that would make the ticket ambiguous or unbounded.

## Acceptance criteria

- Describe observable completion gates, not implementation activity.
- Make every behavior change traceable to at least one criterion.
