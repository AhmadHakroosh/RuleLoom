# Code of Conduct

RuleLoom contributors are expected to keep project spaces focused, respectful, and usable for external contributors and automated delivery agents.

## Expected behavior

- Discuss code, policies, and tradeoffs with clear technical reasoning.
- Assume good faith while still validating claims with repository evidence.
- Keep feedback specific, actionable, and scoped to the work under review.
- Respect privacy, security-sensitive reports, and requests to move sensitive details to a private channel.

## Unacceptable behavior

- Harassment, threats, sustained personal attacks, or discriminatory language.
- Publishing private contact information, exploit details, secrets, or other sensitive material.
- Using project channels to pressure contributors into unrelated work, unpaid support commitments, or unsafe disclosure.
- Asking automated agents to bypass approval gates, branch protection, security policy, or review requirements.

## Escalation

For ordinary conduct concerns, contact the active project maintainers through the repository host's maintainer contact or moderation channel. If the concern includes vulnerability details, private information, or potential abuse, use the private reporting path in [SECURITY.md](SECURITY.md) instead of posting publicly.

Maintainers should acknowledge the concern, gather the minimum necessary context, avoid conflicts of interest where practical, and choose a proportionate action. Possible actions include clarification, moderation, temporary restriction, or removal from project spaces.
